# Phase 8: a bigger project (pre-registered)

**This plan is committed before the first Phase 8 run. Its hypotheses, rules and exclusions do not change after data
exists.** Changes are recorded below as dated amendments.

Kevin, 2026-10-16: three arms (plain, solo, Foragers), and a spreadsheet engine as the project.

## Why

Phases 6 and 7 used a small game (8 modules, 38 hidden tests). Every one of the fifteen runs passed all 38, so they
measured cost and could not see quality. The colony's claim that remains open is that its structure (tasks with
checks, and Forager subagents that each start with a fresh context) buys a better result when a project is too big to
build comfortably in one session. Phase 8 tests that on a project about three times bigger.

## Design

- **Project:** `bench/tally/SPEC.md`, a spreadsheet engine: values and conversions, references, a formula tokenizer,
  parser and canonical printer, evaluation, 36 functions, criteria, a workbook with sheets and names, a dependency
  graph with cycles and an exactly specified recalculation order, row and column insertion and deletion with
  reference fixing, fill, CSV and save files, a text grid, and a command line.
- **Graded by 317 hidden tests** (305 unit, 12 through the command line) in `bench/tally/hidden/tests/`, which no run
  sees. Expected values were worked out by hand from the spec. A reference implementation passes all 317, an empty
  folder scores 0, and each of 14 planted bugs (one per area of the spec) makes at least one test fail
  (`evidence/phase8-tally-planted-bugs.txt`).
- **Arms** (`bench/setup_arm.py --project tally`):
  - `plain`: `SPEC.md` and a 3-line `CLAUDE.md`, no colony.
  - `solo`: the colony as it ships (apiary 0.6.1): the Queen works solo by default and dispatches Foragers only when
    she judges it pays; the guard makes her get the human's approval before creating tasks.
  - `foragers`: the same colony, with a benchmark block in `CLAUDE.md` telling the Queen to give every task to a
    Forager subagent, several at once when several are ready.
- **Order** (interleaved): plain 1, solo 1, foragers 1, plain 2, solo 2, foragers 2, plain 3, solo 3, foragers 3.
- **Same everywhere:** the machine, the model, the prompt "Build the project described in SPEC.md.", the human rule
  (recommended answers, approve plans, no other help), and the Phase 6 instruments with amendments 2 and 3.

## Expectations, stated before the data

My prior (Claude's): a plain session scores high but not perfect, around 285 to 310 of 317. The Foragers arm scores
about the same (no clear difference) at 3 to 8 times plain's tokens. Solo scores about the same as plain at 1 to 1.5
times its tokens. I expect the spec's exactness, not the colony, to decide most of the score.

## Decision rules

Same rule as before: A is clearly better than B on a metric only if A's worst run is better than B's best run.

1. **Does the colony buy quality?** Foragers against plain, and solo against plain, on hidden tests passed. If
   neither colony arm is clearly higher than plain, the verdict is **"no clear quality gain"**, and README and STATUS
   say the colony's value is auditability and enforcement on this project size too. If an arm is clearly higher, the
   docs say which, by how many tests, and at what multiple of plain's tokens and time.
2. **What does it cost?** Each colony arm's median tokens and minutes as multiples of plain's. Reported, not passed or
   failed.
3. Reported, not used for a verdict: the same rule the other way round (plain clearly higher), the tests each run
   failed, first-try closes, overlapping claims (did the Foragers arm run in parallel), and whether a run's context
   was compacted.

## Exclusions

As Phases 6 and 7: contamination, a missing transcript, or a colony run not started in its own run folder
(amendment 1). An excluded run is replaced by a new run of the same arm. No run is excluded for its result.

## Exit gate

| Item | Passes when |
|---|---|
| (a) Benchmark | The reference scores 317 of 317 and an empty build 0 through `bench/grade.py`; the 14 planted bugs are each caught; `setup_arm.py`, `grade.py` and `report.py` handle the second project and the `foragers` arm (`tests/test_bench.py`); CI green. |
| (b) Nine runs | Three per arm, graded, none excluded or each exclusion replaced. |
| (c) Published | `MEASUREMENTS.md` has a Phase 8 section generated by `bench/report.py` with both answers, and README and STATUS match them, whatever they are. |

## Amendments

**1. (2026-10-16, after plain run 1, before any colony run.)** Plain run 1 failed 2 of the 317 hidden tests, and both
were mistakes in the tests and the reference, judged against the spec's own text, not against the run:

- `=SUM()` expected `0`. Section 4.3 says "arguments in brackets are optional" and writes `SUM(x, ...)` with `x` not
  in brackets, so a call with no arguments has the wrong number of arguments: `#VALUE!` (4.1). The same holds for every
  function written `(x, ...)`; the reference allowed zero arguments for nine of them.
- `=COUNTBLANK(A1:A7)` over a range holding `=1/0` expected `2`. Section 4.1 says errors propagate, inside a range
  too, "unless this spec says otherwise for that function"; it says otherwise for `COUNT` and `COUNTA`, not for
  `COUNTBLANK`. The answer is `#DIV/0!`.

Both expectations and the reference were corrected to the spec, and one test was added (`=COUNTBLANK(A1:A4)`, a range
without an error) so COUNTBLANK's counting is still tested: 318 hidden tests (306 unit, 12 command line). The
reference scores 318 of 318 and the 14 planted bugs are still each caught. The spec did not change, so every run
works from the same text; all nine runs are graded with the corrected suite. Plain run 1 scored 315 of 317 under the
original suite and 318 of 318 under the corrected one.

**2. (2026-10-16, after solo run 1.)** Solo run 1 read `A0` in a formula as a name (giving `#NAME?`); the test expected a
`FormulaError`. Section 3.1 says a word "is a reference if it has this form ... otherwise a name", and `A0` is not a
valid reference, so the spec supports both readings. **The rule from now on, applied to amendment 1 too:** where the
spec's text decides a case, the test stands, whichever run it costs; where the text supports two readings, the test
is removed for every run, never flipped. Under that rule the `A0` case is removed (317 tests: 305 unit, 12 command
line), and amendment 1's two corrections stand (`SUM(x, ...)` writes `x` outside brackets, and 4.1's propagation rule
names COUNT and COUNTA as the only exceptions). The reference still scores 317 of 317 and the 14 planted bugs are
still each caught. Plain run 1 passed the removed test, so it loses nothing it should not: 317 of 317. Solo run 1:
316 of 317 (it fails COUNTBLANK over a range holding an error, which the text decides).
